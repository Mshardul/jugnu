# Addon registry

`addons.json` is the public catalog the shell fetches for install/update.

Each entry: `id`, `name`, `version`, `api`, `url` (GitHub Release asset), `sha256`, `summary`, `category`, `subcategory` (optional), `tags` (optional, defaults to `[]`), `description`, `commands` (optional, defaults to `[]`; generated — see below).

`category` is one of: `Clipboard`, `Focus`, `System`, `Info`, `Notes`. `subcategory` nests under a category once it has ≥2 distinct member intents (today only `System` splits into `Dev Tools` / `Monitoring`). `tags` are cross-cutting facets from a fixed vocabulary: `quick-glance`, `toggle`, `background`, `popup-ui`, `dev-tool`, `recommended`.

`commands` is generated by `scripts/sync-registry-commands.sh` from each `addons/<id>/addon.yaml` — do not hand-edit it. `category`/`subcategory`/`tags`/`description`/`summary` stay hand-authored.

See [shell design §2](../docs/architecture/2026-08-22-shell-design.md) and [Browse Catalog design](../docs/architecture/2026-08-23-addon-catalog-browse-design.md). Catalog lists published first-party addons pointing at the `addons-v1.0.0` Release assets.
