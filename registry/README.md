# Addon registry

`addons.json` is the public catalog the shell fetches for install/update.

Each entry: `id`, `name`, `version`, `api`, `url` (GitHub Release asset), `sha256`, `summary`, `category`, `subcategory` (optional), `tags` (optional, defaults to `[]`), `description`, `commands` (optional, defaults to `[]`; generated — see below).

Canonical vocabularies live in `shell/Sources/JugnuCore/CatalogTaxonomy.swift` — `category` is one of `CatalogTaxonomy.categories`; `tags` are from `CatalogTaxonomy.tags`. `subcategory` nests under a category once it has ≥2 distinct member intents (today only `System` splits into `Dev Tools` / `Monitoring`).

`commands` is generated by `scripts/sync-registry-commands.sh` from each `addons/<id>/addon.yaml` — do not hand-edit it. `category`/`subcategory`/`tags`/`description`/`summary` stay hand-authored. `scripts/build-registry.sh` updates zip hashes and URLs in place and preserves those catalog fields; do not redirect its stdout onto this file.

See [shell design §2](../docs/architecture/2026-08-22-shell-design.md) and [Browse Catalog design](../docs/architecture/2026-08-23-addon-catalog-browse-design.md). Catalog lists published first-party addons pointing at the `addons-v1.0.0` Release assets.

## Helpers

`helpers.json` is **not** the catalog. It lists first-party **helpers** (vision rule 4): `id`, `version`, `url`, `sha256`. The shell downloads a helper when installing an addon that declares it; Browse Catalog never shows these rows. Today: `clock`, `python-runtime`. Contract: [addon manifest — Helpers](../docs/addon-manifest.md#helpers).
