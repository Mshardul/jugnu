# Jugnu Shell MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a light Swift `Jugnu.app` (palette + menu bar + hotkey) that installs addons as one zip each from a GitHub registry, indexes enabled commands, runs them via JSON `api: 1`, and cleans up on disable/uninstall — with local mic-mute / focus-toggle / paste-plain addons for v0.

**Architecture:** One `.app` contains only Core + UI. Core owns config, registry/install, command index, runner, cleanup. UI calls Core only. Addons live under `addons/` in-repo, unpack to `~/.local/share/jugnu/addons/<id>/`, never inside the app binary. Dev override loads repo `addons/` without Releases.

**Tech Stack:** macOS 14+, Swift 5.9+, SwiftUI/AppKit hybrid (menu bar + floating panel), Swift Package Manager library `JugnuCore` + Xcode app target, Yams (YAML), CryptoKit (SHA256), URLSession (registry/zips), XCTest for Core.

**Spec:** [docs/architecture/2026-08-22-shell-design.md](../../architecture/2026-08-22-shell-design.md)

## Global Constraints

- Shell binary ships **no** addon code or zip payloads.
- Published addons must **not** require user-installed Python/Homebrew.
- Default hotkey: `option+space`; ⌘Space only via first-run **opt-in**.
- v0 search: enabled-addon commands only.
- Disable/uninstall must run declared `cleanup` (paths + launchd labels).
- Protocol: JSON on stdin/stdout, `api: 1`.
- One zip ↔ one addon; verify `sha256` before unpack.
- Keep UX intentional on the small palette + menu bar (no throwaway stub chrome).
- Prefer TDD on `JugnuCore`; UI tasks verified manually on macOS.

  - `struct RunRequest: Codable` — `api: Int`, `op: String`, `command: String`, `args: [String: String]`
